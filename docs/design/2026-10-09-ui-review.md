# UI review and Meridian refresh (2026-10-09)

Scope: the whole desktop editor, reviewed against published dark-theme and
professional-editor guidance, then re-themed from the Meridian Rift website
(<https://meridian.a13.info/about/>) at the user's request.

Evidence for this review:

- the user's play-test screenshots (MiniStation, light fixtures, context menu);
- the UI source;
- the site's computed styles and `:root` custom properties, read in a browser on 2026-10-09;
- a GL-rendered mock of the editor layout in both themes. Run it with `APHELIONDMM_GL_TEST=1` and `APHELION_THEME_PREVIEW_DIR=<dir>`; see `internal/app/window/theme_preview_test.go`.

**The refreshed theme has not been exercised in the running desktop app.**

## Reference guidance

- **Material dark theme.** Elevation is shown with lighter surfaces, not shadows. The base is dark grey, not black. Accents are desaturated and used sparingly. Text meets at least 4.5:1 contrast at every elevation.
- **JetBrains New UI.** Reduce visual complexity and disclose complex functions progressively. Use one consistent palette, Inter as the UI font, and a compact density mode.
- **WCAG 2.** 4.5:1 contrast for text (AA), 7:1 for body text (AAA), and 3:1 for non-text controls.

## Meridian tokens adopted

All values come from the site's custom properties.

| Role | Token | Value |
| --- | --- | --- |
| Surfaces, darkest to lightest | `--bg-void`, `--bg-0` … `--bg-3` | `#0e0c0b` `#131110` `#1a1714` `#211d19` `#292520` |
| Lines | `--line-soft`, `--line`, `--line-strong` | `#241f1b` `#2e2a25` `#453f36` |

| Accent | `--accent`, `--accent-ink` | `#56d4dc` on `#0d1516` |

| Radii | `--radius-1`, `--radius-2` | 2 px controls, 3 px panels |
| Spacing | `--sp-1` … | 4 px grid |

**Typefaces.** Neuromax, Behavior and Telematic carry no recorded licence and are not adopted. IBM Plex Mono (OFL) was added after approval; see P1.

## Findings and changes

### Done

| # | Finding | Change |
| --- | --- | --- |
| D1 | The inherited theme mixes neutral greys with teal-grey controls. Buttons, frames and tabs share one fill, so hierarchy is flat. | `aphelion/theme` maps every imgui colour role from the Meridian tokens. Elevation uses the surface ramp. Hover, selection and focus are accent tints over the surface; full accent is reserved for check marks, sliders and docking. |
| D2 | No contrast guarantee. | `theme_test.go` checks WCAG contrast for every text-on-surface pairing: AAA for body text and AA for secondary, selected and pressed states. It also checks each button tint and each spectrum colour on the window background. |
| D3 | Saturated named colours (gold `hsl(51,100%,50%)`, pure greens and reds) vibrate on dark surfaces. | Named colours move to the spectrum. Green, red and gold buttons get darker tints so their labels stay readable. |
| D4 | The Instance / Prefab toggle uses a loud green fill. | It now uses an accent-tinted selected segment (`style.ButtonSelected`). |
| D5 | The active tool is gold with black text. | It is now accent with dark ink, the site's call-to-action treatment. |
| D6 | Selected dock tabs are barely distinguishable from inactive ones. | Inactive tabs sit on the tab bar (`void`). The selected tab is raised (`bg-3`) with a trace of accent while its panel has focus. Tested with a minimum step against the tab bar. |
| D7 | Spacing and radii ignore the Interface Scale preference: only fonts grow at 150%. | Theme metrics (4 px grid, 2/3 px radii, hairline borders) are pushed each frame, scaled by Interface Scale. Borders stay 1 px. |
| D8 | The Environment visibility controls take three rows for five buttons, with full-width status text. | One wrapping toolbar row with icons and tooltips. The state line is secondary text. |
| D9 | One-off colours (prefab descriptions in grey 0.6, a red "!" in the environment tree, path-migration tier colours) bypass the theme. | These now use theme roles and the spectrum. |
| D10 | No brand presence. | The site's 2 px spectrum stripe runs under the menu bar. |
| D11 | The mapping-helper dropdown cannot present 236 items. | A searchable, grouped Mapping Helpers tab (Round 6 in the play-test follow-up). |
| D12 | No way back to the old look. | Preferences → Interface → Theme: Meridian (default) or Classic, which is the inherited StrongDMM theme, unchanged. |

### Proposals, done after approval (same day)

The project owner approved IBM Plex Mono and the proposals. The shared building blocks live in `internal/app/ui/uikit`: `Mono`, `SectionLabel`, `MiddleTruncate` / `EndTruncate`, `TruncatedMono` and `EmptyState`.

| # | Finding | Change | Evidence |
| --- | --- | --- | --- |
| P1 | Type paths, variable values and map keys were set in proportional Inter, which makes long DM paths hard to scan. | IBM Plex Mono Regular (OFL 1.1, IBM/plex at `017181e3`; provenance in `internal/rsc/font/plex/README.md`) is the face for variable values, type-path headers, prefab edit summaries, context-menu paths and status-bar coordinates, targets and sizes. It is 16 px, matched to Inter by eye in the preview (15 px read small), with icons merged so the reset button inside value fields keeps its glyph. Inter remains the UI face. The fonts are tagged to the atlas that built them, so a handle from another imgui context is never pushed. | `window/font_owner_test.go` (GL); the full GL suite, which first caught a stale handle in `ui_trace_test.go`. |
| P2 | The map status strip ran unrelated messages together. | Under Meridian the strip is segmented with hairline separators: coordinates in mono; the tool state (Unavailable in red, Gesture in yellow) and its reason; the action and modifiers; the target in mono, middle-truncated; the footprint in mono; the scope; and a lint warning. Z-level controls stay on the right. The hover tooltip and the right-click "Copy full target path" are kept. Classic keeps the single line. | `pmap/panel_status_meridian_test.go` |
| P3 | The tile context menu was very wide. | Paths are middle-truncated in mono to 22 em, with the full path on hover. Object-specific actions (Mapping Helpers, Turn Light Off/On) form their own group after Replace / Reset, shown only when they apply. | `tilemenu` tests |
| P4 | Prefab rows took two lines each. | Under Meridian a row is one line: the name, then the edits in mono, end-truncated with the full text on hover. The text is drawn directly and the row reserves one icon-height line, so the list clipper's stride stays exact. | `cpprefabs/clipper_test.go` (the stride test caught a 1 px drift in the first attempt). |
| P5 | Section labels used body text with ad-hoc colour. | `SectionLabel`: 11 px Inter, uppercase, tracked 0.14 em, in `text-faint`, as the site's micro labels. Used for Pinned / Other in Variables, the colour dialog and the welcome screen. Classic keeps its gold labels. | Preview render. |
| P6 | One density for every screen. | Preferences → Interface → Compact Layout: tighter window, frame, item and cell padding and indent; radii and borders unchanged. | `theme/theme_test.go` |
| P7 | Map overlays used saturated classic colours, fixed at start-up. | Overlays follow the theme through `theme.OnChange`. Each spectrum colour is lightened until it blends into no more sprite pixels than the colour it replaces. Probe over 310 Meridian-Rift DMIs (677,438 opaque pixels), measuring the share of pixels where contrast is below 1.5: red 22.1% → 17.3%; gold 14.9% → 14.3% (yellow); intersect blue 16.8% → 15.7% (cyan); green 14.7% → 15.3%. Green is the only marginal loss, and it keeps a clear hue difference from the art. White fills and borders are unchanged. | `overlay/color_meridian_test.go`; probe `theme/overlay_contrast_probe_test.go` (set `PROBE_ROOT`). |
| P8 | Help → "Support StrongDMM" and other inherited branding remain. | **Not done.** AGENTS.md requires a human-approved branding migration plan, which is separate from UI approval. | — |
| P9 | Empty states varied. | `EmptyState`: wrapped secondary text naming the next action, used in Variables, Prefabs, Search, Environment, Map Lint, Playtest, Mapping Helpers, Collaboration and Path Migration. | Preview render. |

**Variables panel layout (owner request).** The Instance / Prefab toggle and the Find, Settings and Filter row are drawn before the panel's `variables` scroll child. They stay fixed above the list and never scroll away. The earlier preview mock put sample widgets under the list; it now mirrors the real panel.
